How agents use it

An MCP server and a REST API

WhichSitesUse is an MCP server and a REST API with the same operations behind both, so an agent in Claude, Cursor or any other MCP client can look up a domain or pull a list of sites without scraping anything. Results are typed and paginated, and every response includes the crawl date, the credits the call used and the balance left.

An agent usually calls the tools in this order:

  1. find_technologies turns a plain name like "hubspot" into the exact technology, with a note when two products share a name. Free.
  2. count_sites says how many sites match and what the full list would cost. Free.
  3. search_sites returns the list, and its max_credits setting stops it from spending more than you allowed.
  4. lookup_domain returns one domain's full stack.
  5. get_balance shows what's left, and buy_credits gives a person a checkout link to approve, since an agent never pays on its own.

Where the data comes from

Open data, with its limits stated

Every result comes from a monthly snapshot of HTTP Archive's public crawl, which tests the homepage and one inner page of about 16 million websites that real Chrome users visit (methodology). Technologies are detected with HTTP Archive's fork of the open-source Wappalyzer rules, which cover about 3,900 technologies in 108 categories, and Core Web Vitals come from Chrome UX Report field data collected from real visitors.

The crawl runs once a month, so a result can be up to about six weeks old. Small sites with little Chrome traffic are often missing from it, and tools that never load on a public page, like a CRM's back office or payroll software, can't be detected at all. When we don't have a domain we tell you it isn't covered rather than guessing, and that lookup is free.

Common questions

FAQ

How can I tell what CMS a website uses?

Enter the domain in the lookup at the top of this page. The CMS or ecommerce platform shows first, with its version when the site exposes one. You can also look in the page source for a generator meta tag or platform-specific file paths, which are the same clues detection rules look for.

Why does a domain show "not covered"?

HTTP Archive only crawls sites that get enough Chrome traffic to appear in the Chrome UX Report, so new or very small sites are often missing. A "not covered" lookup never costs credits.

How fresh is the data?

We load each monthly crawl after HTTP Archive publishes it, so results are up to about six weeks old, and every result shows its crawl date.

Is there a free plan?

No. New accounts with a verified work email get 250 credits once, and paid plans start at $19 a month.
