Technographics: what the data is and how to use it

Knowing what software a company's website runs tells you who already uses the tool you compete with or build on. That data comes from crawling public pages, so it has blind spots worth knowing before you pay for a list built from it, and a list is cheapest when you count it before you pull it.

// 01  Definition

What is technographic data?

Technographic data is a record of the technologies a company uses, and on the web that usually means what its website runs.

For a website, that record covers the CMS or ecommerce platform, JavaScript frameworks, analytics and tag managers, payment providers, marketing scripts and the CDN, with a version number when the site exposes one. The word is a blend of "technology" and "demographics", and it sits next to firmographics (size, industry, revenue) in most B2B targeting.

Most technographic tools answer one or both of two questions. Asking which sites use a given technology is a reverse search, and it's how you build a list, like every Shopify store in the top 100k. Asking what a given domain runs is a lookup, and it's how you qualify one account before a call. The allbirds.com lookup on our homepage shows 32 technologies in the November 2026 crawl, including Shopify, Shop Pay, Attentive, Impact and the Facebook Pixel, which tells a marketing agency a lot before the first email.

A Shopify agency looking for stores to pitch, a SaaS company looking for sites on a competitor's product and an SEO consultant looking for slow WordPress sites are all asking the first question with different filters.

// 02  Sources

Where does technographic data come from?

Mostly from crawling websites and running detection rules over what the crawler finds.

A crawler loads a page the way a browser would, and detection rules then look for fingerprints in it: a generator meta tag, script and file paths that belong to one platform, HTTP headers, cookies and JavaScript variables. When enough of a technology's fingerprints match, the site is marked as using it. Some providers add other signals on top, such as data from their own browser extension or from job posts, and the source shapes what each one can see.

WhichSitesUse uses one public source. HTTP Archive crawls the mobile homepage and one inner page of sites that real Chrome users visit, every month, and detects technologies with its fork of the open-source Wappalyzer rules, which covers about 3,900 technologies in 108 categories. The November 2026 crawl covered 15,269,451 sites. Core Web Vitals come from the Chrome UX Report, which is field data from real visitors.

Limits that apply to any crawl, ours included

  • Tools that never load on a public page, like a CRM's back office, an ERP or payroll software, can't be detected.
  • Sites with little traffic are often missing, because HTTP Archive only crawls sites that appear in the Chrome UX Report.
  • A monthly crawl lags behind the site, so a result can be up to about six weeks old.
  • Rules only find what they were written for, and a script left behind after a migration still counts as a detection.

// 04  Uses

How do sales and agency teams use technographics?

In prospecting the stack shows who has the problem you solve, and in segmentation it decides which message each account gets.

Competitive displacement

Sites that run a competitor's script and not yours, so every row is a company already paying for the category.

technologies + exclude_technologies

Platform agency

Shopify stores in the top 100k, split by TLD for the countries you sell in.

shopify + max_rank + tld

Performance pitch

WordPress sites failing INP on mobile, so the outreach can open with the problem.

wordpress + cwv inp:fail + mobile

Integration partner

Sites running both HubSpot and Stripe, for a product that connects the two.

hubspot + stripe, match all

Segmenting works the same way: split one list by popularity bucket to decide which accounts get a person and which get an email sequence, or by version to find sites still on an old release of a platform you migrate people off.

// 05  Firmographics

How do firmographic and technographic data work together?

Firmographics tell you whether a company is the right size and shape, and technographics tell you whether it runs the right stack.

WhichSitesUse only covers the technographic side. It returns domains, their technologies, a popularity bucket and Core Web Vitals, with no company size, revenue, contacts or emails. The usual workflow is to pull the domains here and match them against whatever firmographic or contact source your team already uses. Popularity bucket is a rough stand-in for size, since a site in the top 10k gets far more visits than one in the top 1M, but it says nothing about headcount.

// 07  Limits

What technographics can't tell you

A stack is a signal about a company, and it's worth checking before you build a campaign on it.

Whether they're happy with the tool

A detection shows that a script loads, not whether anyone likes it, how much they pay for it or when the contract ends. A site running a competitor might have signed last month.

Whether the tool is still in use

Old tags often outlive the tool they belonged to, so a site can show a technology it stopped paying for. A monthly snapshot also misses anything that changed since the crawl, and the crawl date on each result tells you how old it is.

What runs behind the login

Internal software leaves no trace on public pages. A crawl can see a HubSpot form on a page it loads, but it can't see the finance team's accounting system.

Who to talk to

A list of domains is a list of companies, not people. You'll still need a contact source, and a reason to write that goes beyond "I saw you use X".

// 08  Questions

Common questions

Comparing providers? See the BuiltWith and Wappalyzer comparisons.

What is the difference between technographic and firmographic data?

Firmographic data describes the company, such as its size, industry, revenue and location. Technographic data describes the technology it uses. Most teams join the two, using technographics to find accounts on the right stack and firmographics to keep the ones the right size.

How accurate is technographic data?

It is as accurate as the crawl and the rules behind it. Detection rules are good at tools that leave clear traces in public pages, like a CMS or an ecommerce platform, and they can't see tools that never load on a public page. Check a sample of any list before you act on it.

How fresh is technographic data?

That depends on how often the provider crawls. WhichSitesUse loads HTTP Archive's monthly crawl, so results can be up to about six weeks old, and every response shows the crawl date it came from.

Can technographic data show internal tools like a CRM or payroll system?

Only if the tool loads something on a public page, such as a tracking script or a form. Back-office software that lives behind a login doesn't show up in a website crawl.

What happens when a domain isn't in the data?

On WhichSitesUse the lookup says "not covered" and costs nothing. That's most common with new or very small sites, because HTTP Archive only crawls sites with enough Chrome traffic to appear in the Chrome UX Report.

Can I see when a site added or dropped a technology?

Not on WhichSitesUse today. It returns the current monthly snapshot, so it can show who runs a tool now but not the history of adds and drops.
