// 02  What you can ask

Look up one site, or pull a list of thousands

Both questions run against the same monthly snapshot, so a lookup and a list always agree with each other.

One domain's stack

A lookup returns the platform or CMS, JavaScript frameworks, analytics and tag managers, CDN, fonts and anything else the detection rules found, along with the site's popularity bucket and its LCP, INP and CLS results. Over the API it costs 2 credits, and nothing when the domain isn't covered.

Every site using a technology

A reverse search returns sites at one credit each, and you can narrow it by:

  • technologies a site must use (all or any of them) and ones it must not
  • category and version, such as WordPress 6.x
  • popularity bucket, from the top 1k to the top 10M
  • TLD, and mobile or desktop
  • passing or failing LCP, INP or CLS

// 05  For agents

An MCP server and a REST API

Both expose the same operations, so an agent in Claude, Cursor or another MCP client can look up a domain or pull a list of sites without scraping anything. Responses are typed and paginated, and each one says which crawl it came from, how many credits the call used and what's left.

  1. find_technologies is free and matches a plain name like "hubspot" to the exact technology, flagging cases where two products share a name.
  2. count_sites is also free and tells the agent how many sites match and what the full list would cost.
  3. search_sites returns the list and stops at the max_credits limit you set.
  4. lookup_domain returns a single domain's stack.
  5. get_balance shows the credits you have left, and buy_credits sends a person a checkout link to approve, because an agent can't pay on its own.
{
  "mcpServers": {
    "WhichSitesUse": {
      "url": "https://api.whichsitesuse.com/mcp"
    }
  }
}

Clients that support OAuth sign you in from this alone. Others can add "headers": { "Authorization": "Bearer YOUR_API_KEY" }, and the same key calls these operations at /v1/*.

// 06  Data

Where the data comes from

Every result comes from a monthly snapshot of HTTP Archive's public crawl, which tests the homepage and one inner page of about 15 million websites that real Chrome users visit (methodology). Detection uses HTTP Archive's fork of the open-source Wappalyzer rules, about 3,900 technologies in 108 categories, and the Core Web Vitals are Chrome UX Report field data from real visitors.

That data has gaps, and we'd rather you know them up front. The crawl runs monthly, so a result can be up to about six weeks old. Sites with little Chrome traffic are often missing, and tools that never load on a public page, like a CRM's back office or payroll software, can't be detected at all. When a domain isn't in the crawl, the lookup says "not covered" and costs nothing.

// 08  Questions

Common questions

How can I tell what CMS a website uses?

Put the domain into the free lookup near the top of this page and the CMS or ecommerce platform shows first, with a version number when the site exposes one. If you'd rather check by hand, view the page source and look for a generator meta tag or platform-specific file paths, which are the same clues the detection rules use.

Why does a domain show "not covered"?

HTTP Archive only crawls sites with enough Chrome traffic to appear in the Chrome UX Report, so new and very small sites are often missing. A "not covered" lookup never uses credits.

How fresh is the data?

We load each crawl after HTTP Archive publishes it, which makes results up to about six weeks old, and every result shows the crawl date it came from.

Is there a free plan?

No, but new accounts with a verified work email get 250 credits once, and paid plans start at $49 a month.

Which AI agents can use it?

Any MCP client that supports remote servers can connect, Claude and Cursor included, and anything that can send an HTTP request with an API key can use the REST API instead.
