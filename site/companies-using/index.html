Companies using

Find companies by technology

To find companies by technology, count the websites that run it and then pull the list of domains. WhichSitesUse does both against the 15,269,451 sites in HTTP Archive's November 2026 crawl, over MCP or a REST API. The count and its price are free and each site in the list costs one credit, so you only pay for the part of the list you actually want.

// 01  What you get

A list of websites, which you turn into companies

Each result is a website. It comes with its domain and root URL, its TLD, the Chrome UX Report popularity bucket it falls in, and a Core Web Vitals summary. You also get the technologies from your search that matched, each with its version where the site exposes one, a confidence score and the dates it was first and last seen. In the November 2026 crawl, for example, allbirds.com had 29 technologies detected on its mobile homepage, Shopify and Shop Pay among them, sat in the top 500k bucket and passed all three Core Web Vitals in October 2026 field data.

Most companies run one main website, so a list of domains gets you most of the way to a list of companies, but a result is still a website and not a company record. There are no firmographics, contacts, emails or job posts, and a company that runs the same tool on three domains shows up three times. If you need people to contact, take the domains to the enrichment tool you already use.

// 02  How it works

Count first, then pull the list

Three operations do the work, and the first two are free.

  1. find_technologies turns a plain name like "hubspot" into the exact technology and its slug, tells you how many sites use it, and flags cases where two products share a name.
  2. count_sites takes your filters and returns the total, the split by popularity bucket, and full_list_credits, which is what the whole list would cost. Change the filters and count again until the size is right.
  3. search_sites returns the sites, best-ranked first, up to 1,000 per call. Set max_credits and the call returns fewer sites rather than spend past your limit.
  4. Pass next_cursor back to get the next page. Each page is charged only for the sites it returns, so you can stop as soon as you have enough.

// 03  Filters

Filters you can combine

count_sites and search_sites take the same filters, so a count always matches the list it prices.

ParameterWhat it does
technologiesUp to 20 technology slugs from find_technologies.
match"all" (the default) keeps sites that use every listed technology, and "any" keeps sites that use at least one.
exclude_technologiesDrops sites that use any of these, such as your own product.
categoryEvery technology in a category, for example "Marketing automation".
versionA version prefix, so "6" matches 6.8.1 and not 60.1.
max_rank, rank_bucketsOnly the top N sites, or specific popularity buckets from the top 1k to the top 10M.
tldOne or more top-level domains, such as com or co.uk.
cwvPass or fail on LCP, INP or CLS, measured at the 75th percentile.
deviceMobile, desktop or either. It also decides which device's Core Web Vitals are used.

// 04  MCP and REST

The same calls from an agent or a script

An agent in Claude, Cursor or any MCP client that supports remote servers calls the same operations a script calls over REST, with the same API key. Responses are typed and paginated, and each one says which crawl it came from, how many credits the call used and what's left. For a single domain, the lookup on the homepage is free in your browser.

# MCP tools (server: https://api.whichsitesuse.com/mcp)
find_technologies {"q": "hubspot"}
count_sites       {"technologies": ["hubspot"], "max_rank": 100000}
search_sites      {"technologies": ["hubspot"], "max_rank": 100000,
                   "limit": 500, "max_credits": 500}

# REST: the same operations under /v1
curl -H "Authorization: Bearer YOUR_API_KEY" \
  "https://api.whichsitesuse.com/v1/counts?technologies=hubspot&max_rank=100000"
curl -H "Authorization: Bearer YOUR_API_KEY" \
  "https://api.whichsitesuse.com/v1/sites?technologies=hubspot&max_rank=100000&limit=500&max_credits=500"

REST takes lists as comma-separated values and Core Web Vitals as cwv=lcp:fail. The docs cover every parameter and response field.

// 06  Limits

What the crawl can and can't see

The data is a monthly snapshot of HTTP Archive's public crawl, which loads the mobile homepage and one inner page of about 15 million sites that real Chrome users visit. Detection uses HTTP Archive's fork of the open-source Wappalyzer rules, which know about 3,900 technologies in 108 categories, and Core Web Vitals are Chrome UX Report field data.

A technology only counts if it leaves a trace in what the crawler loads, such as a script, a cookie, a response header or a line of HTML. Tools that live behind a login, like a CRM's back office or payroll software, can't be seen, so a count for those is a count of sites that put something public on the page, and it will be lower than the vendor's customer count. Sites with little Chrome traffic are often missing, and because the crawl runs monthly a result can be up to about six weeks old.

// 08  Questions

Common questions

Is a result a company or a website?

A website. Each result is a domain from HTTP Archive's crawl with the technologies that matched, its popularity bucket and its Core Web Vitals. There are no company records, contacts or emails.

Can I search for more than one technology at once?

Yes. Pass up to 20 slugs in technologies, then set match to "any" for sites that use at least one of them, or leave it at "all" for sites that use every one.

Why is a company I know uses a tool missing?

Either its site isn't in the crawl, which covers sites with real Chrome traffic, or the tool never loads on the pages the crawl visits. Back-office software like a CRM or payroll can't be seen from a public page.

How fresh are the results?

Results come from HTTP Archive's monthly crawl, so they can be up to about six weeks old. Every response says which crawl it came from.
